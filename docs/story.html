An origin story · built in public

A real need. A clear spec. Agents at work.

This did not begin as a software idea. It began with church work that needed to happen across more than one Asana workspace.

01 · The problem

The available bridge stopped at one workspace.

I wanted to use Asana for volunteer and organizational work at my church. The existing Asana MCP server did not support the multiple workspaces I needed—and no setup I tried made it work across them.

The constraint was ordinary. The gap was specific. An AI agent needed a safe way to see and work across every workspace available to one Personal Access Token, without treating all of them as equally writable.

InputOne PAT, not a hand-built workspace list.

ReachThe whole supported Asana API, not a subset.

SafetyRead-only policy that holds per workspace.

02 · The move

Specify the outcome. Let the team run.

Instead of hand-coding the tool, I invested in the brief, the constraints, and the acceptance criteria—then set a spec-coded team of AI agents loose on a shared kanban board.

  1. Plan Turn the need into a testable system.
  2. Execute Build independent slices in parallel.
  3. Audit Attack assumptions and prove findings.
  4. Verify Exercise the integrated behavior.
  5. Release Package, attest, and publish the result.

03 · What shipped

Not a demo. A working tool.

Coverage
249 / 249 API operations One-to-one command coverage from a pinned Asana OpenAPI specification.
Discovery
Automatic multi-workspace discovery The CLI discovers every workspace available to the PAT—no static inventory required.
Guardrail
Per-workspace read-only protection Mutations are stopped before they reach a protected workspace, with ownership resolved from Asana.
Audit
PoC-verified security fixes A dedicated security lane reproduced findings, hardened the system, and returned the integrated tree for verification.
Distribution
CLI, Claude plugin + Vercel skills An attested public release, packaged for direct use and for agent workflows.
